# 公共特性树与领域冻结

从三端系统 SDK 声明和官方目录共同出发。平台 Agent 提取事实；ft-align 拉通三端目标与差异；ft-design 设计公共节点；ft-bind 完整处置 API 用途。平台独有能力仍属于公共树的并集。

节点使用不含层级的稳定 ID。改名和移动保留 ID，拆分/合并留下旧 ID 到新 ID 的继承记录。叶子必须有定义、纳入/排除范围、成功标准和比较维度。空分支仍待下钻，不计叶子。

结构代码检查父子关系、循环、重复身份、同级重名和继承去向；能力边界、同级切分轴、跨域语义重叠由独立 Agent 审查。发布器统一持有正式写入权。

粒度判断以独立比较价值为主，辅以每平台每实现路线的核心符号族数量。替代路线分别展示，不相加；辅助接口另计。重载、多语言和别名没有可验证去重依据时保留，不机械按方法、参数或枚举造节点。来源枚举未闭合时只显示已知下界，不能由数量证明粒度合格。

首批校准范围为相机采集、文件与目录访问、后台任务调度。候选样稿用于确认边界和规则；它们不计正式知识。审批固定骨架、代表叶子、知识样稿及粒度/评级政策对象。后续新增节点可以沿批准骨架扩展；已批准节点语义改变需要重新审查。

领域冻结要求：范围非空、叶子合法、API/官方主题处置守恒、来源无未解决提取缺口、至少一端公开实现、三端正式发行/SDK 基线证据、粒度/覆盖/局部/整合四份真实工作流审查及用户校准确认。冻结同时记录节点语义、绑定、来源、基线与审查指纹。知识研究不能自行修改冻结范围。
