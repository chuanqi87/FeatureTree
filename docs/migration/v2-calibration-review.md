## 粒度发现与修订要求

1. 会话建立、资源关闭、结果回调等步骤不宜仅因存在独立方法就成为叶子。新候选把它们纳入实现链和比较维度，但边界仍需知识样稿检验。
2. 相机两叶目前共享大量 API。是否保留为两个独立目标，要根据连续采集语义、成功标准与实际差异进一步判断，不能仅看名称或共享数量。
3. 文件访问按授权入口和可达范围拆分具有比较价值，但创建、写入、目录授权等均未完成覆盖；Android 已有权限路径读取也不能因为样本没绑定而判不支持。
4. 后台样本把提交、注册、回调拆成多条 route_id，低估完整实现路线的 API 数量。已补上 routes 契约、步骤守恒、完整性校验及审查要求；旧绑定不作新契约合格产物复用。三个范围都需要重新产出带完整路线的绑定。

旧相机叶子的已关联去重 API 各为 11，文件两叶为 11 / 5，后台两叶为 8 / 5；这些只是旧候选中的已知下界，不代表实现所需接口已全部枚举。旧路线计数不用于设定合格区间。没有生成 40/50 硬阈值，也没有把规模参考变成凑数目标。

1. 恢复已配置模型服务，或由用户指定可用 provider/model。不得修改旧工作单的模型、代码指纹或响应。
2. 新建版本化校准运行，保留旧候选为参考；新契约至少重跑 ft-bind 及下游。当前代码已变化，不兼容产物需重新研究；不要强行将旧任务标为成功。
3. 补齐当前稳定 SDK 来源与各范围的完整 API/主题清单；收敛路线与独立叶子边界。
4. 基于通过检查的新候选生成真实知识样稿，执行三端研究、比较、独立审查和逐项评级，展示每项拖低原因及审核单。
5. 样稿和评级标尺可具体审阅后，再请用户确认；随后正式冻结、生产和发布。当前不具备请求最终校准确认的材料。
