# API 粒度计数

实现见 taxonomy/coverage.py 的 size_report。输入为完整声明、经过审核的符号族和用途绑定。输出分别包括全量去重声明数、辅助接口数、每平台/路线核心族数、族身份清单及是否为已知下界。

同一 API 的多种用法可绑定多个能力，必须注明具体用途和文档；替代路线分别计数。数量仅提示异常，拆分须有独立能力目标。无固定 40/50 阈值。校准规则在 config/v2/rules/granularity.json，须结合相机、文件和后台任务的知识样稿人工确认。

绑定产物另有 routes：平台、目标、条件、有序步骤、步骤 API 清单、complete/partial、缺口和证据。完整路线必须能独立达到该叶子的成功标准。提交、回调、完成上报通常是一路线的步骤；不能借拆 route_id 低估接口规模。步骤 API 与绑定必须守恒，纯辅助步骤不能冒充完整路线，partial 强制计数为下界。代码检查结构及引用，ft-granularity 与独立审查核实语义。

路线定义参与叶子绑定指纹；仅修改路线条件或步骤也会使依赖它的知识需要更新。真实校准曾发现后台样本把步骤拆成路线，旧候选保留为待修订材料，不能用于正式冻结。
