# 按实现 API 逐层拆分能力（2026-09-09 修订）

## 决策与范围

用户确认按 Android、iOS、HarmonyOS 分别统计，禁止三端相加。先研究目标节点在三端的实现路径和公开接口，再据此形成下一层特性；每轮只处理直接子节点，父层验收并合并后，子节点可在下一批并行研究。L1 是领域入口；L2 及以下依实际规模决定继续或停止，没有固定叶子层数。

同一平台任一末级节点超过 50 个相关 API 必须继续拆分；目标为不超过 40 个。41–50 默认继续拆分。清单不完整时数量只是已知下界，不能按“小于 40”宣布完成。数量约束和独立能力边界必须同时满足，不按 SDK 目录、方法名、参数或错误码机械建节点。

## API 计数单位

计入实现该能力直接需要的公开函数、方法、构造入口、可访问属性、事件/回调注册入口。一个具名可调用符号计一次；同名重载按一个符号族计，参数组合不扩增数量。模块、类、接口、Kit 与枚举容器是定位依据，不作为一个 API 抵扣其成员；枚举值、错误码、普通结构字段不计入。共享领域 API 在每个使用它的节点分别计入，但同一节点内去重；通用字符串、线程等非领域基础工具不进入清单。

每个 API 必须有规范符号、所属平台、官方 URL 与证据说明。清单由平台研究 agent 交付，数量由程序规范化符号后计算，模型不直接填总数。公开性、设备、权限和版本条件仍单独记录。没有检索到不能认定不支持，也不能声明完整的零 API 清单。

## 顺序与职责

1. 三端实现研究（并行）：提出能力实现路径、相关 API 清单及每条路径的完整性；优先本地官方资料，可调用只读 official_sources 精确检索，必要时读官方页面。
2. scope：消费三端研究，设计当前节点的直接子特性，解释切分轴、实现路径如何归属与未覆盖部分。不得先凭概念画树再要求证据迎合。
3. synthesize：形成节点与逐 API 分配；每条平台候选必须有去向，API 不得静默遗漏。对小而完整的既有空分支可提交“停止拆分”分类，不生成同义独生子。
4. 确定性门：检查直接父子关系、逐 API 引用、遗漏/重复、清单完整性与 40/50 阈值。超限或清单未知的节点不能是 atomic。
5. 独立审查：复核实现路径、公开性、清单完整性、共享 API、拆分边界与停止理由。
6. 锚点检测与整批审查：保持独立；全部通过才可合并设计。
7. 下一层批次：合并后按待展开分支批量派单，继承 API 线索重新核对。API 不足不是强制制造更细节点的理由；可以先完成调查，再确认当前节点为末级。

## 数据与恢复边界

运行保存平台 API 目录、候选 API 引用、节点 API 分配及程序计算的规模评估；正式节点只由协调者写入可追溯的 API 清单与规模。既有节点只允许将未展开、知识仍为 stub 的分支确认成 atomic，不借机改名、迁移含义或覆盖知识正文；知识路径的调整走可恢复事务。

平台证据返工后必须重跑依赖它的 scope、综合和后续验收。纯结构返工可复用平台研究。旧概念优先任务保留为历史记录，不按新规则直接恢复。API 数量是粒度约束，不是整棵树覆盖率；范围和证据未知必须显式呈现。
