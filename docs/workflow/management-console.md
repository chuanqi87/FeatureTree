# 从管理台执行节点分析

管理台提供从节点选取到候选合并的完整入口，底层复用 `scripts/workflow.py` 工作流与原有质量门。

## 发起分析

1. 在特性树的节点行点击“分析”，或打开节点详情。
2. **下钻分析**：细化当前 branch 的子能力，默认新增最多 2 层。atomic 节点不直接下钻。
3. **根节点分析**：从当前节点所属的 L1 领域开始梳理，默认新增最多 1 层。后端根据父子关系解析实际根节点，前端显示真实执行范围。
4. 可以多选互不包含的节点。需要一起汇总验收的分支放在同一任务中，按并发预算并行分析，统一经过跨域审查。
5. 设置版本基线与执行参数，点击“开始分析”。页面跳转到任务详情，后台运行 OpenCode 命名 agent；关闭网页不会取消已启动的进程。

这里的根节点指所属 L1 领域，不是对不存在的全树虚拟节点派单。根节点分析也是树设计流程，不是平台知识正文生产。

## 参数与基线

- 下钻层数、每节点候选预算、并发数、单阶段超时可配置。模型不填时继承 OpenCode 默认模型；指定推理配置时需要同时指定模型。
- 默认“设计基线（版本待核实）”使用当天日期，并保留三端 release/SDK 为 unknown，不冒充已核实的最新版本。
- 已核实基线可按既有 baseline Schema 保存到 `config/workflow/baselines/<名称>.json`，自动出现在管理台下拉框中。界面不接受任意文件路径或 shell 命令。
- 管理台默认共享 6 个并发预算名额；单任务默认 3 个。容量不足时返回明确提示，不暗中创建无界执行队列。可检测到的 CLI 运行也计入容量占用；CLI 自身仍按其运行参数管理预算。

## 任务状态和结果

“分析任务”页每 4 秒刷新一次，展示范围、进度、创建时间、版本基线、模型、每阶段尝试次数和结果。展开阶段可查看划分轴、平台候选、API 入口、审查意见、锚点检测与待核问题；候选结构有独立表格。

| 状态 | 操作 |
| --- | --- |
| 待执行 / 执行中断 | 开始或恢复原任务 |
| 执行中 | 查看阶段进度与已有结果 |
| 执行失败 | 重试失败阶段，成功阶段复用 |
| 需返工 | 按审查意见返工原工作节点，重新验收 |
| 待合并 | 检查候选结果后合并到正式树 |
| 合并待恢复 | 继续原发布事务 |
| 已合并 | 查看历史结果，正式树数据自动刷新 |
| 规则已更新 | 历史可查；新建任务使用当前规则 |

合并继续使用输入/产物哈希、局部和跨域审查、树快照冲突检查及可恢复发布事务。阶段进度达到 100% 只代表任务阶段完成。树覆盖、树冻结和知识确认各自独立。

## 执行边界

后端只开放受约束的创建、启动、重试、返工和发布接口。创建请求携带幂等编号，重复提交返回原任务；正在执行的相同或祖孙范围不能重复启动。同源执行凭证和本机 Host/Origin 校验阻止外部网页触发本地模型运行。

模型工作在独立进程中运行，HTTP 请求不等待模型完成。运行记录仍在 `.workflow/runs/`，进程日志为 `console-runner.log`，管理台重启后可以读取已保存的状态和仍在运行的任务。

当前不提供模型进程的界面取消按钮，也不自动汇总不同快照的独立任务。若多个分支需要一起验收，发起时多选，避免先发布一个独立任务导致其他任务快照过期。

## 验证

新增 8 个后端 HTTP 测试和 2 个前端逻辑测试，覆盖根节点解析、建单幂等、范围/参数拒绝、共享容量、同源请求边界、过期规则可读、返工以及发布质量门。完整 Python 回归为 100 个测试，前端为 17 个测试。

使用真实浏览器在临时目录中跑通“分支入口 → 开始分析 → 自动显示 8 阶段结果 → 查看 2 个候选 → 合入测试树 → 刷新树”。模型返回值为合成测试数据，正式 taxonomy/knowledge 未写入测试节点。这项验证证明管理台操作链路，不替代真实平台研究验收。
