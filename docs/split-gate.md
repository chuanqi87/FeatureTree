# 节点拆分与比较边界

每个节点都是比较单元。拆分服务于明确的任务与差异判断，不以文章长短或某个平台 API 数量决定。

## 何时拆

同时满足以下条件时拆分：

1. 子能力具有可独立描述的任务或语义。
2. 能说清与父节点、兄弟节点的包含和排除边界。
3. 独立比较它能回答一个有用问题。

平台有无、后台模型、权限差异可以成为发现子能力的线索。例如“非前台状态下扫描”有独立执行条件，可作为后台扫描节点。权限名称不同通常写入 permissions_privacy，无须建立平台专用分支。

## 何时停

方法名、参数顺序、语言表面、错误码字面量等在当前节点比较。只有明确产生了独立能力，才继续拆分。文章短不构成合并理由；模板章节数量也不是门槛。

## 边界案例

- BLE 扫描过滤比较条件组合、执行位置与结果语义；批量扫描比较结果聚合交付。批量交付不是过滤能力的缺失项。
- 目标组件调用比较目标定位、参数传递与调用结果。Intent/Want 是平台证据，不是能力定义的标准答案。
- 状态驱动界面更新比较状态如何变为界面变化；声明式/命令式是模型背景。比较文章本身不应充当能力名称。
- 跨设备调用与数据传输保留平台软总线名称为 aliases，比较实际任务。平台独有能力仍归入主树。

## 父节点如何比较

父节点有自己的范围与比较结论，可以写整体架构和共同约束。子节点细节通过 child_index、related_features 或正文链接引用。父结论不自动传播到子节点，子结论也不简单聚合为父节点 full。

每个节点填写 comparison_scope.includes / excludes 与 comparison_dimensions。现有骨架的默认范围仍需逐域细化；结构通过不代表语义划分已经完备。
