# 知识研究原则

当前阶段是从 L1 重建树。树冻结前只准备 API 线索，不开展大规模平台知识生产。项目保留资料工具和知识校验器，不包含活动的模型调度或旧研究任务执行器。

## 新一轮研究

1. 树冻结后重新选择代表性节点，明确每次要回答的问题及写入范围。
2. 核实启动日最新正式系统和 SDK，以手机为主；其他设备、生态服务、库版本和发行版条件分别记录。
3. 按 [官方文档入口](../corpus/entrypoints.md) 和 [证据规则](sources.md)，使用 `official_docs.py` 检索并阅读相关正文。
4. 逐条记录平台支持、比较、事实、证据、未解决问题及 [置信度与真机需求](confidence.md)。
5. 独立阅读复核范围、证据支持关系、版本适用性与推论边界后，采纳到 `knowledge/`。同一文件同一时间只由一位作者负责。
6. 执行 `scripts/refresh.py` 校验数据并刷新视图。机器校验不能替代内容复核。

## 结论边界

- 未检索到正文不能证明不支持；独有、等价和不适用结论需要额外检查替代路径。
- 明确区分官方陈述与依据证据作出的推论。保留 can/must、系统版本、编译 SDK、target SDK 和生态依赖的条件。
- 证据和版本不足时保留 unknown，列出具体缺口。
- 高可信、内容复核通过和真机验证完成分别记录。真机材料必须来自实际执行的样本。
- 旧报告、旧任务预算、旧模型选择、旧版本基线不自动成为新一轮的输入或授权。

未来如果需要并行模型执行，应按当次任务明确分工与验收方式；本项目不自动恢复已归档执行器。
